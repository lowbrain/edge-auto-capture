# ドキュメントの編集

対象は `README.md` / `BUILD.md` / `CONTRIBUTING.md` / `CLAUDE.md` と `.claude/skills/`。
**`USAGE.txt` は対象外**（Shift-JIS。`usage-txt` スキルが扱う）。

このスキルは**手順だけ**を持ち、「何が正しいか」は持たない。
方針の出所は `CLAUDE.md` 冒頭と `CONTRIBUTING.md` §4 で、ここはその適用順を固定するもの。

このリポジトリはドキュメントの二重管理で**繰り返し**実害を出している
（`docs/ROADMAP.md` と Issue の二重管理／CONTRIBUTING の手順が実態からズレて
「解消済みの罠を踏み直せ」と指示する状態 → #51・#114）。経緯の出所は `CLAUDE.md` 冒頭。
**このスキルが防ぐのは次の 1 回。**

---

## 1. 書く場所を決める

`CLAUDE.md` の「出所」表を見る。**書こうとしていることが、その表のどの行か。**

- 行が決まる → そのファイルへ書く。**他のファイルには書かない**（要約も置かない）
- **どの行にも当てはまらない** → 立ち止まる。新しい出所を作る判断になるので、
  勝手に増やさず、まず利用者に相談する

「両方に書いておけば親切」は、このリポジトリでは**そのまま実害の再生産**になる。
片方だけ直った状態を誰も検知できない。

---

## 2. 指し先の波及を洗う

**ファイルを増やす・移す・改名する／節を足す・並べ替える・見出しを変える**ときは、
指し先を持っている側を機械的に洗う。

```bash
grep -rn 'README\|BUILD\.md\|CONTRIBUTING\|CLAUDE\.md\|USAGE\.txt\|§' \
  --include='*.md' --include='*.py' --include='*.js' --include='*.toml' --include='*.yml' . \
  | grep -v '^\./\.venv'
```

拾った中に**索引**が混ざる。典型的に当たるのは `CLAUDE.md` の出所表、`CONTRIBUTING.md` 冒頭、
`README.md` の構成ツリーの 3 枚だが、**この一覧を信用せず毎回 grep の結果を見ること**
（索引が増えていても気づけるように）。

`.claude/skills/` もドキュメントの節を名指ししている。**スキルは grep 対象に含める。**

新しいファイルを足したときは、`tests/test_docs_refs.py` の走査対象の担保
（`test_scan_actually_finds_the_documents`）にも足す。足さないと、番人の視界に
入っているかどうかが保証されない。

---

## 3. 書いてはいけないもの

いずれも**書いた瞬間から古びるのに、何のチェックにも掛からない**もの。

| 書かない | 出所 |
|---|---|
| 残タスクの一覧・現在地 | ロードマップ Issue が正（`CLAUDE.md` の出所表） |
| 「〜時点で未検証」「最終確認: YYYY-MM-DD」等の日付・コミットハッシュ | 同上（`CONTRIBUTING.md` §4） |
| 過去の完了作業の経緯 | git 履歴（`CONTRIBUTING.md` §1-9 の判定基準） |
| 退役語彙（課題タグ） | `CONTRIBUTING.md` 冒頭「退役語彙」 |
| 特定の環境を断定する文（「この機の `.venv` は〜」） | 環境は替わる。**訊く手順**を書く（#114 が実例） |

**ファイルを新設するときは、退役済み旧文書名を再利用しないこと。**
一覧は `CONTRIBUTING.md` 冒頭「退役語彙」。同名で別内容のファイルを作ると、
`git show` で旧文書を読む導線が壊れる。

罠は**現在形で書く**（「以前は X だった」ではなく「X にしてはいけない。理由は…」）。
経緯の形で書くと、実装が変わって嘘になったことを誰も検査できない。

---

## 4. 直したら回す（必須）

```bash
pytest tests/test_docs_refs.py
```

何を縛っているかは、そのファイルの docstring が正。ざっくり言えば
「本文が名指ししている先（`*.py`・GitHub リンク・Issue 番号・節番号・相対リンク・
見出しアンカー）が実在すること」で、**半分だけ書き換わった状態**を落とす。

- **落ちたら、番人ではなく参照側を直す。** 例外を足すのは、歴史的言及として
  残すと決めたときだけ（許可リストへ**理由付きで**置く）
- コードにも触れたなら 4 点セット（`verify` スキル）

- **指し先を直したファイル**があればそれも（波及は本文より見落とされやすい）
- 番人テストの結果

## 6. スコープ外

- **`USAGE.txt`** — Shift-JIS。`usage-txt` スキルへ
- **内容そのものの正誤** — 散文が実装と合っているかは機械で落とせない。
  ここが扱うのは構成・出所・指し先であって、記述の正しさの検証ではない
- **新しい出所を作る判断** — §1 で当てはまる行が無かった場合は、書かずに相談する
